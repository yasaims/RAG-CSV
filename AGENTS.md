# AGENTS.md

This file provides guidance to AI Agents when working with code in this repository.

## **IMPORTANT**

- Do not edit this file unless explicitly instructed to do so.
- Only follow links to other documents when the current task actually requires it.
- Keep comments simple. Do not include issue numbers, ADR numbers, or change history.

## Repository Overview

Develop a Q&A assistant for safety officers at a fictional factory, "Kaminashi Seiki Co., Ltd.", that answers questions by referencing accident record data.

## Implementation Layers / Commands

`README.md`

## Specification

- See `SPEC.md` for the finalized specification.
- The current development phase is Phase 1 (local, CPU operation).


## VALUES

- Readability, extensibility, auditability, fault tolerance.


## Verification

- If you change `core/` or `evals/`, run the evaluation with the `verify-eval-baseline` skill before committing.
- If it does not pass, stop the commit and report to the user.
- Do not update the baseline just to turn red into green. Updating it is an explicit decision to "adopt the current level as the baseline."

## Git Flow

Adopt GitHub Flow.

### Rules

1. **Never commit directly to `main`.** Always cut a working branch and merge via Pull Request.
2. Branch names follow the `<type>/<short-description>` format (e.g. `feat/api-schema`, `feat/rag-pipeline`, `docs/architecture`, `fix/csv-parse`).
3. Commit messages follow Conventional Commits format:
   - `feat:` new feature / `fix:` bug fix / `docs:` documentation / `test:` tests / `refactor:` refactoring / `chore:` config/misc.

## Notes on How to Proceed

- **Comments, documentation, and PR/commit messages should be concise Japanese.**
- Commit in logical units of change. Do not split commits unnecessarily just to trace the work flow.
- Record design decisions (design based on data characteristics, how answer quality is evaluated/improved, extensibility) in documentation.
- Record any remaining work as GitHub issues.
- The root [README.md](README.md) is expected to be maintained as a README for team development.
